## How To: Predicting Boundaries

The boundary conditions are calculated by multiplying boundary footprints (generated by the LPDM) with CAMS concentration curtains.
The boundary footprints are expected to be in the `fp` file, with attribute name `particle_locations_{direction}` where `direction` can be `n,s,e,w`.
The concentration curtains should be stored in the `bc_path` in `config.py`.

The following functions calculate the convolution:

https://github.com/GATES-Lab/GATES_LPDM_emulator/blob/5c1560e6c17cb7245bdabf9c91ac98d793153482/gates/data/load_background_data.py#L7

https://github.com/GATES-Lab/GATES_LPDM_emulator/blob/5c1560e6c17cb7245bdabf9c91ac98d793153482/gates/data/load_background_data.py#L62


### Training and Predicting
To train the GATES model for background prediction, set up a parameter file (you can see [an example parameter file here](https://github.com/GATES-Lab/GATES_LPDM_emulator/blob/unify_boundary_updated/parameter_files/parameter_template_boundary_full.json))
The set up is the same as the GATES model, plus the following info:
```
    "background_setup": {
        "detrend": true, 
        "use_auxiliary_bc": true,  
        "auxilary_bc_levels":[4, 5, 6, 7]
    }
```
where
- `"detrend"` (bool) determines whether to subtract the detrending factor, which is the mean CAMS concentration in the southern bound
- `"use_auxiliary_bc"` (bool) determines whether to append concentrations from CAMS as inputs to the model (extracted from the midpoint of the lat/lon)
- `"auxilary_bc_levels"` (list of ints) indicate the the heights to extract the CAMS concentrations from (if `use_auxiliary_bc` is true)

Plus the following parameters in the existing section `"model_parameters"`
```
    "model_parameters":{
        "decoder":"conv", 
        "num_classes":1,
        ...
```
If the `"decoder"` parameter is `"conv"`, the model `GraphSatelliteForecasterConvClassifier` is used, where the decoder 
1) uses an MLP to translate from the mesh to the regular grid 
2) the grid is formatted as an image of size `(S,S,node_dim)` 
3) the grid is passed through a CNN block of `stride=2`, so that `(S,S,node_dim) -> (S/2, S/2, 32) ->  (S/4, S/4, 8)` (parameters `stride=2`, `conv_hidden_channels = 32` and `conv_out_channels = 8` are hardcoded)
4) The output is flattened into conv_out_channels * S/4 * S/4 and passed through a linear layer, that produces the prediction

If the `"decoder"` parameter is anything else, the decoder
1) uses an MLP to translate from the mesh to the regular grid
2) the grid (after step 1 above) is flattened (shape `(size·size·output_dim)`)
3) the flattened vector is passed through a linear layer, that produces the prediction

The parameter `"num_classes"` determines whether the baselines are predicted as the sum of all sides (if `num_classes=1`) or one for each side (if `"num_classes"=4`, currently untested!).

**Launching training**

Launch the train file with `python train_boundary_model.py parameter_template_boundary_full.json`


**Launching predicting**

Launch a prediction run with the following command, where `trained_model_20260520_144557` is the name of your trained model which should be at `save_models_dir` in `config.yaml` (or pass a specific model path with arg `--model_path /path/to/folder/`)
```python predict_boundary_model.py  --test_year 2016   --reference_model trained_model_20260520_144557   --checkpoint best ```
